# وضعیت پورت موتور (PORT STATUS)

> شفافیت کامل — سند زنده‌ی پیشرفت «اجرای خودِ بازی» (فازهای ۳–۵).

## خلاصه برای کاربر

هدف این فاز: وقتی روی اپ می‌زنید، **موتور واقعی Zero Hour** (کد بازشده‌ی EA، نگهداری TheSuperHackers) داخل همان اپ بوت شود — نه اپ جدا و تکه‌تکه.

## انجام شده (این کامیت)

- موتور آپ‌استریم با پین دقیق `f8ba7eb` داخل CI فچ و با سری پچ پورت، **کامپایل کامل** می‌شود (هسته + کد بازی Zero Hour + WWLib/WWMath/WWSaveLoad/WW3D2).
- لایه‌ی `win32shim` (شبیه‌ساز سطح API ویندوز روی POSIX) + پچ‌های LP64/clang.
- جریان بوت واقعی: `AndroidMain` معادل WinMain (memory manager → command line → GameMain → engine init/execute) — `CreateGameEngine` پورت‌شده.
- JNI: `nativeStartEngine` موتور را با پوشه‌ی فایل‌های بازیِ کاربر بالا می‌آورد؛ `nativeEngineStatus` فاز بوت را برای صفحه‌ی عیب‌یابی گزارش می‌کند.
- CI: fetch خودکار آپ‌استریم + اعمال پچ + بیلد arm64 داخل APK.

## باقی‌مانده (مسیر بحرانی، به ترتیب)

1. **بیلد arm64 در CI سبز شود** (clang/NDK ممکن است خطاهای تازه‌ای نسبت به g++/Linux بدهد — طبیعیِ چرخه‌ی پورت).
2. **رندرر GLES3** پشت `IRenderBackend`/DX8Wrapper (فاز ۵ — سنگین‌ترین بخش؛ منو و نقشه).
3. **صدای AAudio/OpenSL** پشت `AudioManager` (جایگزین Miles که لودرش روی اندروید fail-fast می‌کند).
4. **ورودی لمسی** به.MessageStream موتور (TouchMapper موجود به رویدادهای موتور وصل می‌شود).
5. مرحله‌ی پایداری: pause/resume، حلقه‌ی رندر روی EGL surface، کیفیت روی Adreno/Mali.

## یادداشت معماری

- هیچ‌چیز از فایل‌های EA باندل نمی‌شود؛ فایل‌های بازی توسط خود کاربر وارد می‌شود (ویزارد SAF موجود).
- رندر/صدا «شبیه‌سازی» نمی‌شوند: بک‌اند واقعی GLES پشت seam رسمی آپ‌استریم (`IRenderBackend`) ساخته می‌شود — همان مسیری که آپ‌استریم برای جداسازی DX8 باز کرده.
- شفافیت: تا وقتی فاز رندرر تمام نشود، بوت موتور «headless» است؛ صفحه‌ی عیب‌یابی وضعیت واقعی موتور را نشان می‌دهد.

## v0.1.3 — جریان «کلیک → اجرای مستقیم بازی»

- `BootActivity` لانچر یکتا شد: کلیک روی آیکون → اگر فایل‌ها آماده باشند مستقیم `GameActivity` تمام‌صفحه (افقی، بدون نوار سیستم) باز می‌شود.
- فقط بار اول یک صفحه‌ی تکی پوشه‌ی بازی را می‌گیرد (بدون ویزارد چندمرحله‌ای)؛ نوع بازی از فایل مهر خودکار تشخیص داده می‌شود.
- `GameDataResolver`: مسیر واقعی پرونده‌سیستم برای موتور — یا مسیر خام همان پوشه (بدون کپی) یا کپی یک‌باره به حافظه‌ی برنامه (با ادامه از نقطه‌ی قطع)؛ پس از آن هیچ دسترسی/سؤالی لازم نیست.
- `GameActivity` واقعاً `nativeStartEngine` را صدا می‌زند و وضعیت فاز بوت موتور را صادقانه نشان می‌دهد + دکمه‌ی نبرد شبکه‌ای (هات‌اسپات).
- رفع قطعی CI: CMake آپ‌استریم `3.28+` می‌خواهد → نسخه‌ی CMake به `3.31.1` ارتقا یافت؛ `engine/port/jni/generals_jni.cpp` (پل JNI بیلد موتور‌دار) اضافه شد.
